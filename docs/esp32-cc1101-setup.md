# Считыватель Нартис на ESP32 + CC1101 — сборка от начала до дашборда

Пошаговая инструкция для повторения рабочего сетапа: счётчик Нартис с радиоканалом
RF433-2 → ESP32 с модулем CC1101 → ESPHome → Home Assistant.

Ничего не подключается к самому счётчику и не вскрывается: ESP32 притворяется выносным
дисплеем НАРТИС-Д101-2 и опрашивает счётчик по радио. Считыватель питается от обычного
USB-блока и должен стоять в зоне Wi-Fi и в пределах радиосвязи со счётчиком.

**Что проверено на живом железе.** Трёхфазный Нартис, счётчик на опоре, считыватель в
доме (ноябрь 2026):

- RSSI счётчика около −70 dBm;
- цикл опроса 4–6 с;
- все ответы с сошедшейся CRC;
- энергия по тарифам, U/I/P по фазам, частота и часы читаются.

За 3 часа сверки (181 цикл) мощность каждой фазы совпала с U·I, а сумма фаз — с общей
мощностью. Однофазный вариант описан ниже, но нами не проверялся.

| --- | --- |

## 1. Что купить

| Деталь | Комментарий |
| --- | --- |
| **ESP32 DevKit V1** (ESP-WROOM-32, 30 pin) | любая клон-плата с USB. Под неё рассчитан корпус |
| **CC1101 433 МГц с SMA-антенной** | распространённая синяя плата «CC1101 V2.0» с разъёмом 2×4 (продаётся и как E07-M1101D-SMA). Кварц 26 МГц. 433-МГц версия нормально работает на каналах Нартиса 440–444 МГц |
| 7 проводов Dupont мама–мама | 10–20 см |
| USB-кабель и блок питания 5 В | хватит любого от телефона |

> ❌ **Не берите Si4432.** Мы прошли этот путь до конца: передача работает, счётчик
> отвечает, но Si4432 **не может демодулировать ответ**. Индекс модуляции сигнала
> счётчика h = 2·25 кГц / 1200 бод ≈ 41, а демодулятор Si4432 рассчитан на h ≤ 32: байты
> размножаются в 6–10 раз, CRC не сходится никогда. Подробности — в `SI4432.md` ветки
> `si4432-support`. Подходят только **CC1101** или **CMT2300A**.

## 2. Подключение

Модуль питается от **3.3 В**, не от 5 В. **Антенну накрутить до первого включения**:
передача без антенны вредит выходному каскаду.

| CC1101 | ESP32 DevKit V1 | в YAML |
| --- | --- | --- |
| VCC | 3V3 | — |
| GND | GND | — |
| SCK | GPIO18 | `pin_sclk` |
| MISO (SO / GDO1) | GPIO19 | `pin_miso` |
| MOSI (SI) | GPIO23 | `pin_mosi` |
| CSN | GPIO5 | `pin_cs` |
| GDO0 | GPIO27 | `pin_gdo0` |
| GDO2 | не подключать | — |

Если на плате CC1101 нет подписей у разъёма 2×4, у нашей синей «V2.0» нумерация была
такая (нечётные — один ряд, чётные — другой; пин 1 обычно отмечен квадратной площадкой):

```
  2 VCC   4 CSN   6 MOSI   8 GDO2
  1 GND   3 GDO0  5 SCK    7 MISO
```

Сверяйтесь с подписями на вашей плате, если они есть: у разных продавцов разводка разъёма
может отличаться.

```
 ESP32 DevKit V1                         CC1101 433 MHz
 ┌──────────────┐                      ┌───────────────┐
 │          3V3 ├──────────────────────┤ VCC           │
 │          GND ├──────────────────────┤ GND           │
 │       GPIO18 ├──────────────────────┤ SCK           ├── SMA ── антенна
 │       GPIO19 ├──────────────────────┤ MISO / GDO1   │
 │       GPIO23 ├──────────────────────┤ MOSI          │
 │        GPIO5 ├──────────────────────┤ CSN           │
 │       GPIO27 ├──────────────────────┤ GDO0          │
 │    USB  5V   │                      │ GDO2  (n/c)   │
 └──────────────┘                      └───────────────┘
```

Пины можно переназначить на любые свободные GPIO: SPI здесь программный, аппаратный блок
`spi:` не нужен. Не используйте GPIO6–11 (флеш) и, по возможности, GPIO0/2/12/15
(strapping).

## 3. Конфиг ESPHome

1. Возьмите [`examples/esp32-cc1101-3ph.yaml`](../examples/esp32-cc1101-3ph.yaml).
2. Заполните секреты по образцу [`examples/secrets.yaml.example`](../examples/secrets.yaml.example):
   - `nartis_serial` — **12 цифр серийного номера с шильдика, в кавычках**;
   - Wi-Fi;
   - API-ключ: `openssl rand -base64 32`;
   - пароли OTA и резервной точки доступа.
3. Частоту канала задавать не нужно: компонент вычисляет её из серийного номера и
   печатает в лог при старте. Например, `440.400 MHz`.

Компонент подключается прямо с GitHub:

```yaml
external_components:
  - source: github://Muxee4ka/esphome-nartis-rf-2-meter@main
    components: [nartis_rf_2_meter]
```

В этом форке есть фикс под **ESPHome 2026.11+**: там удалили `format_hex_pretty()`, и
исходный компонент перестал собираться.

### Трёхфазный счётчик

Это главная ловушка: в однофазных примерах напряжение — `0x14`, ток — `0x1B`. **Трёхфазный
счётчик эти теги не присылает**, и сущности просто остаются пустыми. Нужно:

| Что | Теги | Откуда |
| --- | --- | --- |
| Энергия всего / T1 / T2 | `0x00` / `0x01` / `0x02` | `list_2` |
| Напряжение L1 / L2 / L3 | `0x15` / `0x16` / `0x17` | `list_2` |
| Мощность, сумма | `0x20` | `list_2` |
| Ток L1 / L2 / L3 | `0x1C` / `0x1D` / `0x1E` | **`fix_2`** |
| Мощность L1 / L2 / L3 | `0x21` / `0x22` / `0x23` | **`fix_2`** |
| Частота, часы | `0x28`, `0x29` | `list_2` |

Поэтому `sources: [list_2, fix_2]`. Без `fix_2` токов и мощности по фазам не будет.
Подписи токов у производителя сдвинуты на один (см. [`tags.md`](../tags.md)): `0x1C`
— это действительно фаза A, проверено по нагрузке.

### Однофазный счётчик

*Не проверено нами — по документации компонента.* Возьмите тот же конфиг и замените:

- три напряжения на одно: `tag: 0x14`, имя `Voltage`;
- три тока на один: `tag: 0x1B`, имя `Current`;
- удалите `Active power L1–L3` (`0x21–0x23`);
- `sources: [list_2]`. Если тока или напряжения нет — добавьте `fix_2`.

Компонент сам пишет в лог, какой тег из конфига ни разу не пришёл. По этому логу
конфиг подгоняется под конкретный счётчик.

## 4. Прошивка

### Вариант А — ESPHome Device Builder (аддон Home Assistant)

1. **New Device** → придумайте имя → **Skip** → **Edit** у новой карточки → вставьте конфиг.
2. **Secrets** (вверху справа) → допишите секреты из `secrets.yaml.example`.
3. **Install**:
   - первый раз — **Plug into this computer** (плата по USB в компьютер, браузер Chrome
     или Edge) либо **Manual download** → прошить файл через
     [web.esphome.io](https://web.esphome.io);
   - дальше — **Wirelessly** (OTA).

### Вариант Б — командная строка

```bash
pip install esphome
cp examples/secrets.yaml.example secrets.yaml     # заполнить
esphome run examples/esp32-cc1101-3ph.yaml       # первый раз по USB, дальше по OTA
esphome logs examples/esp32-cc1101-3ph.yaml      # смотреть лог
```

### Если плата не входит в режим прошивки

Многие клоны DevKit V1 не умеют автосброс. Прошивальщик пишет `Failed to connect` /
`Wrong boot mode`. Порядок:

1. Зажмите **BOOT**.
2. Коротко нажмите **EN**.
3. Отпустите **BOOT**.
4. Сразу запускайте прошивку.

Через esptool: `--before no-reset --baud 115200`. Драйвер USB-UART — CP210x или CH340,
смотря что стоит на плате.

### Builder собирает старую версию компонента

ESPHome кэширует `external_components` (по умолчанию на сутки). Если компонент в
репозитории обновился, а сборка берёт старый код, есть два варианта:

- удалите кэш `/config/esphome/.esphome/external_components/<hash>/` в контейнере аддона;
- временно поставьте `refresh: 0s` в блоке `external_components`.

## 5. Проверка

В логе (`DEBUG`) при старте видна частота канала. Каждый цикл выглядит примерно так:

```
[D][nartis_rf_2_meter]: TX DI 0xF202 attempt 1 (28 bytes)
[D][nartis_rf_2_meter]: RX rssi=-70 dBm (78 bytes)
[D][nartis_rf_2_meter]:   TAG 0x15 = ... -> 'Voltage L1' = 181.5 V (list)
```

Что считать хорошим результатом:

- `Last read OK` = on;
- RSSI стабилен. У нас −70 dBm через стену дома до опоры;
- часы счётчика (`Meter clock`) совпадают с реальным временем;
- для трёхфазного: `P Lx ≈ U Lx × I Lx`, а `P L1 + P L2 + P L3 ≈ Active power`. Если не
  сходится — значит, перепутаны теги.

Иногда на скачущей нагрузке `P` и `U·I` расходятся в одном кадре: значения сняты в разные
моменты. По истории в среднем всё должно сходиться.

## 6. Home Assistant

1. HA сам найдёт устройство (интеграция ESPHome). Если нет: **Настройки → Устройства →
   Добавить интеграцию → ESPHome**, адрес платы, API-ключ из секретов.
2. Сущности получат префикс из `friendly_name`: `sensor.nartis_meter_voltage_l1` и т. д.
3. **Дашборд:** [`dashboards/nartis-meter-3ph.yaml`](../dashboards/nartis-meter-3ph.yaml).
   Как вставить целиком или по карточкам — написано в шапке файла. На нём:
   - гауджи напряжения по фазам, зелёная зона 207–253 В по ГОСТ;
   - U/I/P по фазам;
   - показания по тарифам;
   - качество связи;
   - суточные графики и столбики потребления по дням.
4. **Панель «Энергия»:** **Настройки → Панели → Энергия → Потребление из сети** →
   `sensor.nartis_meter_energy_import_total` (или T1 и T2 по отдельности, если нужен учёт
   по тарифам).

## 7. Установка на месте

- Плата должна стабильно видеть Wi-Fi. У нас работает на −72…−55 dBm. При −74 dBm и
  хуже бывали `Auth Expired` и переподключения.
- Задайте плате **резерв DHCP** (статический адрес) на роутере и тот же адрес в
  `wifi: use_address:`. Тогда OTA и HA не потеряют устройство.
- Антенну — вертикально. Металлический щит и стены съедают сигнал. CC1101 передаёт
  примерно на 10 дБ слабее родного дисплея (+10 против +20 дБм). Если счётчик не
  отвечает, сначала переставьте считыватель ближе.

## 8. Корпус

[`enclosure/esp32-cc1101/`](../enclosure/esp32-cc1101/) — коробка с крышкой под эту
сборку.

- **Компоновка.** Обе платы стоят пинами вверх, Dupont-провода надеваются сверху. В
  одном торце окно под USB, в другом — отверстие под SMA, антенна накручивается снаружи.
  Есть ушки для крепления к стене и вентиляционные щели.
- **Размеры.** Снаружи 97.5 × 33.5 × 36.6 мм.
- **Крышка.** Надевается на юбку с рёбрами натяга и держится на двух защёлках.
- **Печать.** PETG, 0.2 мм, 3 стенки, заполнение 15 %, без поддержек: коробка дном вниз,
  крышка верхом вниз. Примерно 75 мин и 34 г на коробку, 21 мин и 8 г на крышку
  (Bambu Lab P2S).
- **Исходник.** `nartis_case.py` на [build123d](https://github.com/gumyr/build123d). Все
  размеры — константы в начале файла. `pip install build123d && python nartis_case.py`
  пересоберёт STL/STEP. `sections.png` — разрезы.
- **Допущения.** Плата ESP32 51.5 × 28.5 мм, отверстия CC1101 — по чертежу модуля. Если
  ваша плата другого размера, поправьте константы и пересоберите.

## 9. Если что-то не так

| Симптом | Что делать |
| --- | --- |
| Сборка падает на `format_hex_pretty` | ESPHome 2026.11+ с исходным компонентом. Берите этот форк (`@main`) |
| Код компонента обновили, а собирается старый | кэш `external_components`, см. раздел 4 |
| Счётчик молчит (RSSI нет) | проверьте `address` (12 цифр, в кавычках), антенну, расстояние. Затем `rx_offset` ± несколько сотен Гц. Затем `sources: [list_1]` |
| Счётчик слышно (RSSI есть), но CRC не сходится | `radio: foc_carrier_sense_gate: true`, сравнить долю удачных циклов |
| Энергия есть, а напряжения/тока нет | трёхфазный счётчик с однофазными тегами — см. раздел 3 |
| Токов и мощности по фазам нет | добавьте `fix_2` в `sources` |
| `Previous cycle still running` | увеличьте `update_interval` или уменьшите `rf_retries` |
| Плата не подключается к Wi-Fi | слабый сигнал (−74 dBm и хуже). Без Wi-Fi плата поднимает точку `Nartis-Meter-Fallback`, через неё можно поправить сеть |
| В HA сменился адрес платы | **Настройки → Устройства → ESPHome → ⋮ у записи → Перенастроить**, указать новый адрес |

Полное описание параметров компонента и таблица всех тегов — в [README](../README.md)
и [`tags.md`](../tags.md).
